# Nueva spec

Úsala cuando haya un ticket sin spec, o cuando una regla de negocio cambie.

1. No modifiques modelos, servicios, pantallas ni tests de producto en este paso.
2. Crea o actualiza un archivo en `docs/specs/`.
3. Incluye reglas DEBE y NO DEBE, la tabla criterio → verificación y la tabla ticket → archivos.
4. Si la regla viene de un hueco del PRD, cita la decisión. No inventes otra.
5. Deja el commit de la spec listo antes de cualquier commit de implementación.
